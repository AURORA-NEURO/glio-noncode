# Assurance history observatory archive registry diff audit query

The diff-audit query boundary provides bounded inspection over a verified
registry-diff audit. It is read-only: it never changes the twelve-check audit
decision and never adds source paths, timestamps, or private attribution data.
Every result includes the source audit address, its exact query, a bounded
record window, and a deterministic query content address.

## Resources and filters

The supported resources are:

- `summary` — one aggregate audit summary record.
- `checks` — all twelve audit check records.
- `passed` — only passing checks.
- `failed` — only failing checks.
- `evidence` — check IDs, pass states, source evidence addresses, and check addresses.

All resources support `check_id`, case-insensitive public `text`, `offset`, and
`limit` filters. `passed=true|false` can further restrict check and evidence
records. The default page is 50 records, the maximum page is 256 records, and
the maximum offset is 2,048.

## CLI

Query two exact five-file registry packages through the diff-audit boundary:

```text
python -m glio_noncode.cli \
  module-workbench-execution-packet-archive-store-replication-packet-diff-release-window-review-store-catalog-packet-review-gate-history-observatory-packet-registry-federation-assurance-gate-review-decision-ledger-assurance-history-observatory-archive-registry-diff-audit-query \
  --baseline ./baseline-registry \
  --candidate ./candidate-registry \
  --resource evidence \
  --check-id content-address \
  --format markdown
```

The query contract commands are suffixed with `-query-schema`,
`-query-result-schema`, and `-query-capabilities` on the diff-audit command.

## HTTP

The query endpoint is the audit child route:

```text
/v1/module-workbench/execution/packet/archive/store/replication/packet/diff/release-window/review-store/catalog/packet/review/gate/history/observatory/packet/registry/federation/assurance-gate/review/decision-ledger/assurance-history-series/release-registry/federation/gate/review/decision-ledger/assurance-history/observatory/archive/registry/diff/audit/query
```

Supply `baseline`, `candidate`, `resource`, and optional `passed`, `check_id`,
`q` or `text`, `offset`, `limit`, and `format=json|csv|markdown`. The schema
and capability endpoints are `/query-schema`, `/query-result-schema`, and
`/query-capabilities` below the audit route.

## Downloaded-data demonstration

The standalone demo can inspect the downloaded registry generated by the
observatory archive demonstration:

```text
python examples/release_registry_federation_gate_review_decision_ledger_assurance_history_observatory_archive_registry_diff_audit_query_demo.py \
  --baseline "$TEMP/glio-noncode-history-observatory-demo-current/registry-v1" \
  --candidate "$TEMP/glio-noncode-history-observatory-demo-current/registry-v1" \
  --resource passed --check-id content-address
```

The result is one passing content-address check with a replayable query
address, while `--resource failed` returns an empty bounded page for the same
verified real-data self-diff.
