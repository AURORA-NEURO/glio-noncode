# Workbench release frontier assurance planes

The four operation results are only the beginning of a safe release. The supporting
planes make the workbench state inspectable and repeatable.

1. The data audit closes source, row, role, balance, and private-marker checks.
2. The adapter registry binds exactly four operation values to four functions.
3. The schema receipt declares required fields and nested collection shapes.
4. The evaluator compares expected and observed states without hiding controls.
5. Metrics count rows, roles, operations, states, and issue codes descriptively.
6. Lineage connects public source IDs to records and execution addresses.
7. Reconciliation keeps mismatches visible and prevents silent promotion.
8. Policy preserves the aggregate research-use boundary.
9. Quality gates combine data, fixture, adapter, schema, and reconciliation checks.
10. Replay compares evaluation addresses over the same fixture.
11. Views expose stable row identity, role, state, issues, and address.
12. Queues route every review, blocked, and rejected row.
13. Handoffs retain queue IDs, blocked IDs, and descriptive metrics.
14. Integrity checks close fixture, record, execution, and identity addresses.
15. Depth checks assert 16 rows, 4 operations, 5 sources, 80 checks, and role balance.
16. Validation matrices cover state, issue, role, integrity, and safety.
17. Evidence matrices join source count, input address, output address, and state.
18. Access manifests declare public URLs and prohibited input classes.
19. Failure injection demonstrates conservative behavior on malformed and empty data.
20. Artifact inventories retain fixture, evaluation, run, and source receipts.
21. Release receipts bind run ID, fixture identity, and quality closure.
22. Summaries and reports provide human-readable descriptive projections.
23. Provenance receipts bind run, policy, and schema addresses.
24. Freshness receipts preserve source version declarations without mutable fetches.
25. Compatibility receipts bind schema and adapter counts.
26. Release checks re-evaluate quality, integrity, and compatibility.
27. Stage manifests and transcripts preserve ordered execution.
28. CSV export provides a narrow, stable review handoff.
29. Review SLAs and protocols turn issues into explicit next actions.
30. Claim boundaries prevent lifecycle receipts from becoming clinical claims.
31. Recovery mappings quarantine foreign context and repair incomplete inputs.
32. Resource accounting makes row and check size visible.
33. Operational mappings describe the action for every state.
34. Query and partition views provide deterministic reviewer access.
35. Bundles join artifact, release, and summary addresses.
36. Observability records run identity, stage count, and gate state.

Every plane is deterministic over the checked-in aggregate fixture. None of the
planes silently invents records, claims, or human decisions. A successful release
means the declared workbench contract closed; it is not a certification of a user
interface, a scientific result, or a regulated product.
