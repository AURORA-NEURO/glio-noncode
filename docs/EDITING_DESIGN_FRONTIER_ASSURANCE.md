# Editing-design frontier assurance

The assurance mesh is intentionally split into independently callable planes:

- provenance and lineage
- expected/observed reconciliation
- research policy and claim boundaries
- schema-gated quality
- deterministic replay
- stable views, queues, and handoff
- content integrity and depth
- control, validation, and evidence matrices
- public access and failure injection
- diagnostics, artifact inventory, and release acceptance
- runtime manifest, source registry, freshness, compatibility, and invariants
- execution plan, observability, audit log, transcript, report, and export
- recovery, performance, operations, compliance, query, partitions, scenarios, resources, and bundle
- provenance graph, decision ledger, review assignment, schema diagnostics, context boundary, and source receipt index

Each stage has a sequence, duration, output address, detail, and content address. Each plane has a stable receipt with explicit acceptance. The final runtime decision is the conjunction of the core gates and every assurance plane, including review SLA, publication policy, reproducibility, attestation, and state-transition checks.
