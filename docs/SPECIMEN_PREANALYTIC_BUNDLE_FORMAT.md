# Specimen preanalytic bundle format

The C13-C16 bundle is the compact release projection for the public aggregate
specimen evidence plane. It is generated by
`SpecimenPreanalyticEvidenceBundleBuilder` and can be written as JSON, CSV,
or Markdown. All formats describe the same twelve entries.

## Envelope

The JSON envelope contains:

| Field | Meaning |
| --- | --- |
| `bundle_id` | stable bundle identity |
| `fixture_id` | source fixture identity |
| `context_key` | exact six-part context |
| `state` | `accepted` or `review` |
| `entries` | sanitized per-record receipt rows |
| `evaluation_address` | evaluator report address |
| `scenario_address` | scenario matrix address |
| `content_address` | canonical bundle address |
| `entry_count` | derived entry count |
| `passed` | derived accepted-state convenience flag |

The canonical address body includes all fields except `content_address`,
`entry_count`, and `passed`. Derived fields are not part of tamper verification.

## Entry schema

Every entry has:

| Field | Meaning |
| --- | --- |
| `entry_id` | `entry:<record_id>` |
| `record_id` | fixture record identity |
| `operation` | C13, C14, C15, or C16 operation ID |
| `role` | positive or control |
| `expected_state` | fixture-declared state |
| `observed_state` | adapter-observed state |
| `issue_codes` | sorted issue-code tuple |
| `output_address` | sanitized result address |
| `entry_address` | canonical entry-body address |

The entry address is computed from every entry field except its own address.
An entry mutation therefore fails verification even if the bundle envelope was
not changed manually.

## State rules

An accepted bundle is allowed only when the full evaluation and scenario matrix
pass. Controls remain entries in an accepted bundle because their expected
state is review and their review transition is part of the evidence.

A review bundle may be generated only with an explicit `allow_review` option.
It retains all issue codes and observed states. It cannot be mistaken for an
accepted publication because `state` remains `review` and the normal CLI
returns a non-zero status for the source evaluation.

## JSON

JSON is the default format. It is sorted and indented for inspection, with a
terminal newline. Consumers should ignore derived count and pass fields when
recomputing the content address.

## CSV

CSV has one row per entry and the following stable columns:

```text
entry_id,record_id,operation,role,expected_state,observed_state,
issue_codes,output_address,entry_address
```

Issue codes are joined with semicolons. A control with no issue code is
rendered as an empty field, though the checked-in controls all retain at least
one declared issue.

## Markdown

Markdown is a human-review projection. It contains the fixture, context,
state, component addresses, and one table row per entry. Addresses are shown
inline so a reviewer can compare a bundle to the evaluator and reconciliation
reports without opening the raw fixture.

## Boundary

The bundle never embeds the fixture `records` collection or an operation
`payload`. It retains only identifiers designed for the aggregate fixture,
operation and state labels, issue codes, and content addresses. The builder’s
tests serialize every supported format and check that restricted raw-field
names do not appear.

## Verification

The builder verifies:

1. the envelope content address;
2. every entry content address; and
3. the accepted/review state selected by the source evaluation.

The CLI command is:

```powershell
python -m glio_noncode build-specimen-preanalytic-bundle `
  examples/specimen-preanalytic-public-aggregate.json `
  --output preanalytic-bundle.json
```

Use `--format csv` or `--format markdown` for the alternate projections. Use
`--allow-review` only when intentionally inspecting a review fixture.

## Compatibility rules

The bundle ID may change the content address but not the entry schema. Adding
a field requires a new address-body test and a boundary review. Renaming an
existing field requires a documented format revision. Derived convenience
fields may be added without changing the address body only when their values
are deterministic functions of already addressed content.
